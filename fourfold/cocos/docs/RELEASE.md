# 微信小游戏发布与变现核验 · v0.1

## 一、工程配置（必做）
1. 使用 **Cocos Creator 3.8.8**，打开 `cocos/` 工程，预览 `assets/scenes/Main.scene`。
2. 项目构建发布选 **微信小游戏**，填写自己账号的 AppID。必须启用「生成开放数据域工程模版」。
3. 构建后检查 `build/wechatgame/game.json` 是否有开放数据域根目录设置，并确认 `build/wechatgame/openDataContext/index.js` 使用的是此工程自定义版本（不是 Cocos 模板里的演示假数据）。实际路径和键值以微信开发者工具构建结果为准。
4. 微信开发者工具导入 `build/wechatgame`，测试真机按钮点击、字体显示、横竖屏、安全区、悬浮广告、不遮挡微信菜单。
5. 注册/备案/内容合规、名称/图标版权、隐私指引与平台要求由小游戏主体在公众平台完成。使用微信朋友关系的能力要按后台实际要求声明，不能因为有代码就当作自动获权。

## 二、微信好友榜
- 主域：`Game.ts` 使用 `wx.setUserCloudStorage` 保存 `FF_DAILY_V1`，其值为 `YYYY-MM-DD|score|moves|seconds`。当天每日挑战正常通关均可上传，包括使用过提示的成绩；上传本机今日最佳，步数少优先、同一步数时用时短优先。
- 提示次数不参与分数、荣誉、最佳成绩比较或分享资格。旧版带提示的本地最佳若仍然更好，会保留并重算分数，避免继续以旧的0分上传。
- 开放数据域：`openDataContext/index.js` 调用 `wx.getFriendCloudStorage`，过滤非当日及无效记录，直接按步数、用时排序后绘制到 `sharedCanvas`，由 Cocos `SubContextView` 展示。它是微信好友榜；网页没有微信好友数据，也不构造假名次。
- 页面：日期、我的今日最佳、名次/好友/步数/用时四列、前三名金银铜标记、每页5位好友、刷新、上下页及今日挑战入口；读取中、无数据、读取失败各有明确状态。头像不可用时使用昵称首字占位。
- 主域发送 `{type:'fourfold-rank',day,key,width,height,page:0}` 读取数据，翻页发送 `{type:'fourfold-rank-page',delta:-1|1}`；开放域在已读取结果中翻页并限制页码，不重复获取云数据。
- `Main.scene` 的未激活节点 `RankViewTemplate` 预先配置 `SubContextView` 设计分辨率 **720×640**。打开排行榜时实例化、按同一比例排布，组件加载后再发送绘制消息；开放域画布保持720×640，避免运行时修改设计分辨率导致留白或纹理尺寸错误。
- 不做模拟排名、虚构头像、虚构名次。若用户无好友纪录/权限拒绝，显示真实空状态或错误提示。请在真实微信中验证主域和开放数据域的通信及授权。
- 作弊风险：客户端可篡改步数；涉及奖品时必须改用服务器端校验。

## 三、提示与广告（未开通广告也可先上线）

**当前阶段：正式版本免费提示。** `cocos/assets/scripts/Game.ts` 默认配置为：

```ts
const HINT_MODE:'free'|'rewarded'='free';
const AD_IDS={rewarded:'',banner:''};
```

- 保留「提示」按钮，点击即显示一步提示；普通关每局最多5次，每日挑战每局最多2次，显示剩余次数；本局用完后不再发放，重开或进入新一局恢复额度。免费模式不创建或请求激励视频广告。
- 使用过提示仍正常计分、评定荣誉和参与好友榜，与提示是否通过广告获得无关。
- 空 Banner ID 不请求 Banner。广告能力尚未开通不影响玩家正常解题。

**广告开通后：取得真实广告位 ID，测试通过后再构建发布。** 将配置改为：

```ts
const HINT_MODE:'free'|'rewarded'='rewarded';
const AD_IDS={rewarded:'微信后台提供的真实激励视频adUnitId',banner:''};
```

- `free` / `rewarded` 是明确的构建配置；仅填入 ID 不会自动结束免费期，也不会随流量自动切换。
- 激励视频：玩家主动点「提示」且本局还有额度才展示；仅在 `onClose({isEnded:true})` 后发一次提示并扣一次额度。普通5次、每日2次的上限与免费模式一致，额度用完不再请求广告。提前关闭、加载失败、旧局回调均不发奖励、不扣次数；连续点击只发起一次请求。
- 首次展示失败时最多加载并重试一次；返回主页、换关、同关重开后，旧请求不会给新一局发提示；组件销毁时解除监听。
- `rewarded` 模式缺少 ID、微信 SDK 或广告能力时，显示暂不可用，仍可继续解题；不会自动按免费模式发奖励。Cocos 本地预览需要免费提示时使用 `free` 配置；独立网页试玩仍免费。
- Banner 单独可选：取得真实 Banner ID 才填写，在**通关结算**后创建；新局隐藏并销毁。
- 开通要求、类目/主体资格、隐私/广告规则以微信公众平台实时后台为准，不使用未经核实的固定 UV 门槛承诺。

## 四、分享与裂变
- `wx.shareAppMessage()` 带 `mode=daily&day=...&beat=...`。好友点开后拿到同一局面，看到挑战目标。
- 主域已主动调用 `wx.showShareMenu()`；不通过分享回调发奖励，不强迫分享，不承诺分享后给道具/解锁。
- 浏览器试玩的 Web Share / 复制链接与正式微信分享是不同环境，需要单独验收。
