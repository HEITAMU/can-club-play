# 微信小游戏发布与变现核验 · v0.1

## 一、工程配置（必做）
1. 使用 **Cocos Creator 3.8.8**，打开 `cocos/` 工程，预览 `assets/scenes/Main.scene`。
2. 项目构建发布选 **微信小游戏**，填写自己账号的 AppID。必须启用「生成开放数据域工程模版」。
3. 构建后检查 `build/wechatgame/game.json` 是否有开放数据域根目录设置，并确认 `build/wechatgame/openDataContext/index.js` 使用的是此工程自定义版本（不是 Cocos 模板里的演示假数据）。实际路径和键值以微信开发者工具构建结果为准。
4. 微信开发者工具导入 `build/wechatgame`，测试真机按钮点击、字体显示、横竖屏、安全区、悬浮广告、不遮挡微信菜单。
5. 注册/备案/内容合规、名称/图标版权、隐私指引与平台要求由小游戏主体在公众平台完成。使用微信朋友关系的能力要按后台实际要求声明，不能因为有代码就当作自动获权。

## 二、微信好友榜
- 主域：`Game.ts` 使用 `wx.setUserCloudStorage` 保存 `FF_DAILY_V1`，其值为 `YYYY-MM-DD|score|moves|seconds`。仅当天未使用提示的通关上传。
- 开放数据域：`openDataContext/index.js` 在 `wx.getFriendCloudStorage` 里查询该键，过滤旧日期，排序后绘制到 `sharedCanvas`，由 Cocos `SubContextView` 展示。
- 不做模拟排名、虚构头像、虚构名次。若用户无好友纪录/权限拒绝，显示真实空状态或错误提示。请在真实微信中验证主域和开放数据域的通信及授权。
- 作弊风险：客户端可篡改步数；涉及奖品时必须改用服务器端校验。

## 三、广告（上线前填 ID）
在 `cocos/assets/scripts/Game.ts` 顶部替换：

```ts
const AD_IDS={rewarded:'真实激励视频adUnitId',banner:'真实Banner adUnitId'};
```

- 激励视频：玩家主动点「提示」才展示；只在 `onClose({isEnded:true})` 后发提示，广告未播完不发奖励。
- Banner：在**通关结算**后创建；新局隐藏并销毁，避免误触、挡棋盘。
- 未开通流量主时保持空值；测试版本免费提示并标记此次成绩不入榜，不把灰色框伪装成广告展示。
- 开通要求、类目/主体资格、隐私/广告规则以微信公众平台实时后台为准，不使用未经核实的固定 UV 门槛承诺。

## 四、分享与裂变
- `wx.shareAppMessage()` 带 `mode=daily&day=...&beat=...`。好友点开后拿到同一局面，看到挑战目标。
- 主域已主动调用 `wx.showShareMenu()`；不通过分享回调发奖励，不强迫分享，不承诺分享后给道具/解锁。
- 浏览器试玩的 Web Share / 复制链接与正式微信分享是不同环境，需要单独验收。

- [ ] 实际包体与资源，微信隐私、备案、平台审查
