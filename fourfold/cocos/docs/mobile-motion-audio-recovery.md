# 0.8.27 · 手机旋转未变化与完全无声

## 复现与已知边界

用户反馈旋转从早期到 2.4 秒始终没有变化，按钮和旋钮完全无声。不能再将该反馈解释为音量不足，也不能用独立 Chrome 的非零波形证明用户手机已正常播放。

正式入口的无版本参数、旧版本参数和 0.8.26 参数，公开响应均为 0.8.26，主脚本、音频模块、旋转模块与 MP3 已逐字节核对。静态响应 max-age=600；没有发现四格 Service Worker 或 Cache API。没有证据证明本次正式服务端漏发，也没有用户端证据可以断言是客户端缓存。

发现三种不同入口：正式游戏含音效，普通旋转 2400ms，但系统 reduced-motion 分支只有 240ms；实时美术预览独立控制器没有音效，reduced 分支 180ms；内嵌离线美术预览仍固化旧 1200ms 且无音效。美术预览不能当作正式游戏的新版本验收入口。

## 动画修复

网页和原生采用游戏自己的 `turnMotion=full|gentle` 偏好，默认完整模式；用户明确要求的慢旋转不再被系统偏好自动缩短。两模式都使用共享 2400ms 常量。轻柔模式淡出，在完全透明时换位，再淡入，不大幅移动图块。装饰 CSS 仍尊重系统减少动态偏好。

设置记录真正一次动作的开始、完成或取消时间、目标时长、模式和动画路径。取消耗时标为取消，不冒充完成耗时；还没转过时不填假的 2.4 秒实测值。

## 音频修复

旧控制器缓存一个 `resuming` Promise，只有 finally 才清空。若它永不结束，后续每个真实手势都等旧 Promise，不会再次调用 resume；同样不应无限期等待 suspend。新控制器每次有效手势可以同步重新请求恢复，等待有明确时限，动作代次和一次性 token 仍阻止旧声音复活。触摸预热改在 pointerup / touchend，鼠标可在 pointerdown，真实点击播放仍会自行恢复。

用户明确选择手机兼容模式时，支持 AudioSession 的环境请求 `playback`；不支持或设置被拒绝时使用一个复用的 HTMLAudioElement。每个触点只有一个后端，HTML play 在有效操作的同步段调用，不先等待 fetch，不用每个触点创建新元素。落位仍由动画真实完成后触发；加载过慢、策略拒绝、取消、静音、离页都会失效该请求，不安排补响。

标准模式保留系统默认类别。兼容模式属于媒体播放，可能在设备静音模式下发声，也可能影响其他应用的音频混播；入口清楚说明媒体音量语义。游戏的关闭音效偏好始终有效，不用无声音轨、录音权限、循环保活或两个后端同时播放。兼容模式暂停或退出时恢复本页原来拥有的会话类别。

设置里的“已启动 / 已结束”是程序可观察到的状态，不等于扬声器已出声。按下、落位、主动试听分开保存，打开设置的普通按钮声音不会覆盖旋钮故障证据。主脚本和音频模块各自提供内部构建标识，HTML、脚本或模块版本不一致可被看见。

## 主源依据

- [WebKit 252746](https://bugs.webkit.org/show_bug.cgi?id=252746)：Web Audio 的 ambient 与媒体元素的 playback 在静音开关、混播方面语义不同。
- [WebKit 251532](https://bugs.webkit.org/show_bug.cgi?id=251532)：工程师提出 AudioSession playback 对 silent mode 的处理建议；不能据此推断用户设备静音状态。
- [HTML 用户激活模型](https://html.spec.whatwg.org/multipage/interaction.html#activation-triggering-input-event)：鼠标 pointerdown 与非鼠标 pointerup、touchend 的激活时点不同。
- [AudioSession 支持说明](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/audioSession)：该接口并非所有浏览器都支持，必须检测与处理失败。

生产方法与替身验证可以检查时序、状态与取消，真实浏览器可以检查页面和可观察播放请求；这些均不能替代用户实际 iPhone / 内嵌浏览器的扬声器试听。若仍无声，需要当前游戏实例设置中的检查截图，而不是再次推测缓存、音量或系统静音开关。
