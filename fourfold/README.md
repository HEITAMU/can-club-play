# 四格诡局 · FOURFOLD

微信好友同关挑战 × 3×3 四格旋转益智游戏。目标：转动任一 2×2 方块（顺时针或逆时针），用尽量少的操作把九枚印记归位，争夺真实好友最优解。

> 工程版本：**Cocos Creator 3.8.8**。网页试玩和 Cocos 小游戏通过 `cocos/assets/scripts/Core.js` 与网页的 `CoreHardWeb.js` 使用一致的规则与固定题库。网页试玩版不冒充 Cocos 渲染版，微信好友榜与微信广告仅能在微信小游戏内运行。

## 试玩

打开本文件夹 `index.html` 的静态站点（推荐 GitHub Pages；本地用 `python3 -m http.server 8000`），直接手机或电脑浏览器开玩。建议手机竖屏。键盘 `1–4` 旋转四个位置、空格切换旋转方向、R 重开。

## 0.8.5 四格旋转反馈

- 点击旋转点后，对应四格以金色边框突出显示，其他五格轻微变暗；四张图案沿中心做可见的90°弧线移动，旋钮同步转向。
- 网页与原生共用 `TurnMotion.js`：总时长460毫秒，包含聚焦、旋转和落位。中途适度收拢四张图案，保持完整可见，结束时准确匹配原稿各个格子的实际宽高。图案与数字保持正立。
- 一次动画完成只记一步；动画期间不累积连点。返回、重开、尺寸变化或销毁页面会取消未完成的动作，旧回调不会改变新一局。
- 系统开启“减少动态效果”时，网页缩短为轻微淡入淡出，仍完整更新棋盘和步数。
- `tests/turn-motion.test.mjs` 检查四个旋转点、两个方向及原稿不等宽格子的轨迹；`tests/turn-preview.html` 使用真实游戏页面检查中途效果和动作结束后的状态。

## 0.8.4 排行榜原画与通关弹窗

- 「好友荣誉榜」接入确认的星空领奖台原画；前三名常驻，下方从第4名开始每页3人，头像、昵称、日期、步数与用时为动态内容。网页保留真实本机最佳及微信好友榜空态，不生成演示好友。
- 排行榜按页面完整宽度等比显示854×1842原画，短屏使用纵向滚动，独立点击区至少44px；原生开放域画布与主域底图保持同一比例。
- 通关弹窗采用新绘制的透明星空冠饰面板，统一步数与时间信息牌；背景、边框和按钮为美术，荣誉、成绩和按钮文字由程序填入。
- 普通第1—17关通关后，叉号与主按钮都进入下一关；第18关进入当天每日挑战；每日挑战回到当前已解锁普通关。一次通关只推进一次，连续点击与旧弹窗回调不能跳过关卡。其他弹窗的关闭行为保持原样。
- 新美术坐标记录于 `cocos/assets/resources/art/rankLayout.json`；资源来源和接入说明见 `cocos/docs/ART-INTEGRATION.md`。

## 提示额度与好友荣誉榜

- 普通关每局最多 **5 次**提示，每日挑战每局最多 **2 次**；按钮显示剩余次数，重开或进入新一局恢复额度。
- 使用提示正常计分、评定荣誉、保存最佳成绩和分享战绩。排行榜只比较步数，其次比较用时，不因提示扣分或取消资格。
- 独立「好友荣誉榜」页面包含日期、我的今日最佳、名次/好友/步数/用时四列和今日挑战入口。网页只显示本机真实最佳及微信好友榜空状态；微信版显示真实好友、前三名领奖台和分页。
- 当前仍为免费提示模式；以后启用激励视频也使用同样的每局额度，只有实际获得提示才扣一次，广告中途关闭或失败不扣。

## 手机宽度适配

主页、每日挑战都使用手机的完整可用宽度，桌面容器上限460px。`layout.mjs`分别计算原画、信息牌、棋盘和按钮的位置，不再把整张长图按视口高度缩成中间窄条。所有美术仍来自已确认的原稿，日期、步数、时间与九块棋子继续实时运行。

- 390×650：主页插画382px宽，每日棋盘外框374px宽；320×568分别为312px和304px。
- 主页短屏只裁掉原图顶部装饰和下部空纸，保留标题、星窗、书本，三个菜单按钮独立等比排列。
- 每日挑战在短屏上将返回/日期/设置放在同一行，提示与挑战按钮并排；足够高的屏幕保留竖向排列。
- 更短的视口允许页面内部纵向滚动，仍保留近全宽棋盘和至少44px的主要触控区域。
- 参考坐标仍为 `cocos/assets/resources/art/referenceLayout.json`；原稿棋盘外框817×765、内盘747×694，素材不因适配而拉伸。

真实 iframe 检查页 `tests/layout-preview.html` 覆盖390×650、390×844、320×568、390×600和460×936，检查宽度利用率、素材比例、按钮命中与重叠。原生接入与验证边界见 `cocos/docs/ART-INTEGRATION.md`。

## 玩法闭环

- **18 份闯关档案**：完成当前局面才解锁下一关，存档自动保存至本地。
- **每日同题**：固定 UTC+8 日期，保证同一天每个人拿到完全一样的题目；分享时携带日期和挑战步数。
- **真正的最优解**：9! 个合法排列组成的状态图，使用双向广度优先搜索；理论最少步数与实际提示均由算法算出，非凭空设定。
- **荣誉**：最优解、极致推演、逻辑高手、破局者；理论最优与玩家得分显示分开。
- **公平分数**：主要比较步数，相同步数比较用时；普通关5次、每日挑战2次的每局提示额度内正常参与排行，提示不扣分。上传本机今日最佳，较差的重试不会覆盖该纪录。
- **自愿分享**：公开战绩+同题链接，不做强制分享、转发后解锁、邀请奖励、虚构好友。
- **分阶段提示**：未开通广告时正式版本也免费提示；开通后配置真实广告 ID 并显式切到激励视频模式。两种模式共用每局额度，提示始终不影响排行，结算 Banner 单独可选。

```text
cocos/assets/scenes/Main.scene        启动场景，附加 FourfoldGame 和排行榜视图模板
cocos/assets/scripts/Game.ts          原生 Cocos 组件、微信分享/广告/好友榜
cocos/assets/scripts/Core.js          两端共用规则与双向 BFS

cocos/build-templates/wechatgame/
  openDataContext/index.js             好友排行的独立开放数据域

```

## Cocos Creator 打开方式

1. Cocos Dashboard 安装 **3.8.8**，选择“导入项目”，目录指向本仓库的 `cocos/`（其中包含 `package.json` 和 `assets/`）。
2. 在资源面板打开 `assets/scenes/Main.scene`，点击 **预览**；场景会由 `Game.ts` 创建 Canvas、UI、相机和交互按钮。
3. 打开「项目 → 构建发布 → 微信小游戏」，填自己的 AppID，勾选“生成开放数据域工程模版”，构建。`build-templates/wechatgame/openDataContext/index.js` 应当拷贝进构建产物。
4. 完整发布流程见 `cocos/docs/RELEASE.md`。`Game.ts` 默认 `HINT_MODE='free'`、`AD_IDS` 为空，未开通广告也能以免费提示模式上线；取得真实广告位后，再切换 `rewarded` 模式并重新构建、真机验证。

## 已做验证 / 未做验证

**已验证：** 原生共用规则脚本的 Node.js 测试（旋转逆操作、题目可解、最优路径、日期题稳定、成绩排序与分享参数）；TypeScript 静态解析。**未验证：** 没有在本环境运行 Cocos Creator 3.8.8 编辑器/微信开发者工具进行真机打包与审核，因此不能声称“已上线/通过微信审核”。微信 AppID、流量主广告位与隐私协议需要实际账号配置。好友关系链在网页无法测试。GitHub Pages 网页已实际验证主页、普通关、每日挑战、顺逆时针、首关通关与下一关解锁、重开、提示、分享复制反馈及荣誉榜跳转；每日页只显示一个“每日挑战”，棋盘使用原稿外框817∶765和内盘747∶694的比例。网页验证不替代 Cocos 引擎渲染或微信真机测试。

**注意：** 好友排名目前采用 `wx.setUserCloudStorage` 客户端分数上传。它适合好友娱乐竞技，但不能防止故意修改客户端。若有现金奖品或正式竞技赛事，须加服务端规则校验/重放验证。日常同题依 UTC+8 日期轮换；不依赖未经证实的市场规模数字。
