# 罐头远征队：现有角色动作制作与复用规范 v1

适用版本：0.26.69；记录日期：2026-11-15。
项目：HEITAMU/can-club-play；目标平台：H5 试玩、微信小游戏。

## 1. 用户已确认的方向

用户认可 `motion-prototype.html` 中橘座、火花的完整原画短过渡效果。随后要求按这套方法处理现有角色，并提供本规范供后续窗口复用。

用户否定 `orange-puppet.html` 的分层拼接试作，明确要求回到前一版。石墩外形重设计已叫停；新黑猫立绘、模板页、分层补绘素材均不是正式美术，不得自动接入。

本方法是「完整角色关键姿势 + 连续轻形变 + 短时间交叉过渡」。不是完整骨骼动画，不是将两张画做成连续关节动作，也不保证达到《剑与远征：启航》的制作水准。不得把浏览器 CPU 提交耗时当作微信真机帧率。

## 2. 美术与角色不变量

1. 使用现有 `assets/finished/` 角色图集；本次不重画、不拆肢、不改变比例或服装。
2. 保持完整角色姿势中的头身比、持物手、尾巴位置和道具数量一致。
3. 原始数据源模板是画风依据：清晰棕色描边、柔和配色、轻纸纹、简化毛发、圆润猫体型。模板中的部件拆图不代表允许使用已否定的拼接动画。
4. 不用整体横向压扁、纵向拉长或大幅缩放伪造动作；待机主要是胸腔轻呼吸、尾巴小幅滞后，脚底固定。
5. 保留角色专用动作：火花提灯、扳手投掷、石墩攒盾重拳。不要统一成同一种出手姿势。

正式角色 ID：orange 橘座，ink 阿墨，milk 奶糖，spark 火花，mint 薄荷，bolt 扳手，pudding 石墩，star 星斑。`pudding` 是存档兼容 ID，不应因中文名变化而重命名。

## 3. 本次接入的核心算法

唯一公共参数位于 `painted-transition.mjs`：

```js
const start = 0.41;
const end = 0.59;
const t = clamp((fraction - start) / (end - start), 0, 1);
const mix = t * t * (3 - 2 * t);
```

`fraction` 是两张相邻完整姿势之间的局部进度，不是整次攻击的时间。

- 前 41% 保持前一张完整画。
- 中间 18% 用 smoothstep 完成短过渡。
- 后 41% 保持后一张完整画。
- 不再让两个不同轮廓在整个姿势区间都半透明重叠。
- 两层透明度相加必须等于 1，保证角色不忽明忽暗。
- 若前后是同一帧，只绘制一次；透明度为 0 的层不绘制。
- 现有细微网格形变继续逐帧运行，不因保持关键姿势而停止。

注意：18% 是区间比例，不是 18 毫秒。不要反复套用此曲线；套两次会让过渡窗口过窄。

## 4. 专用短过渡的例外

扳手的专用动作、石墩的蓄盾/重拳由独立姿势轨道提供 `From / Cel / Mix`。它们已经有短过渡（例如石墩的姿势切换为 75ms）。通过 `paintedLayers(..., {short:true})` 保留已有时长，不再压到原时长的 18%。否则约 13.5ms 的换帧容易出现硬跳。

例外仍统一执行：相同帧合并、零权重跳过、总不透明度保持 1。不要为追求全队参数相同破坏专用动作。

## 5. 代码入口与责任

| 文件 | 职责 |
| --- | --- |
| `painted-transition.mjs` | 公共短过渡曲线与绘制层选择 |
| `finished-roster-renderer.mjs` | 除火花外七名伙伴的完整原画渲染；保留扳手/石墩专用轨道 |

| `shidun-motion.mjs` | 石墩专用姿势选择 |
| `shield-punch.mjs` | 石墩真实技能规则，本次不改 |

H5 与微信构建使用同一套渲染源文件。本次正式接入的是 Canvas 路径；试验页中的 WebGL 分支未作为已验证的微信方案推广。

## 6. 接手时的标准流程

1. 阅读本文件和最新用户指令。核对 git 当前分支、远端 head、未提交改动，避免覆盖别的窗口工作。
2. 找到现有角色 ID、正式图集和专用动作轨道。优先复用原画；没有用户明确要求时不重设计外形。
3. 将过渡接到渲染层。保留 `windup / travel / impactAt / hold / duration` 的原始值，不用动画回调决定真实伤害。
4. 检查待机→蓄势→出手→命中→收势→待机；有专用机制的角色增加蓄盾、中断、死亡、投射物释放检查。
5. 正常速度检查整体观感；半速和拖动进度检查双手、道具、边缘重影和落脚。不要仅检查截图就宣称动态流畅。
6. 原始画作有穿帮时应单独修原画并重新验收；缩短交叉过渡不能修正错误的持物手、四肢或道具。
7. 运行对应测试及构建，再发布。最终附可打开的实际页面，不只提供设计说明。

## 7. 战斗规则不能被动画改写

本游戏是回合制。角色每回合的行动次数、技能命中次数及伤害由原战斗逻辑决定。

禁止因为多画了两次挥拳就新增一次命中；禁止为视觉连贯擅自改变能量、护盾、控制、中断和冷却。近战到目标面前、远程投射物飞行仍遵循既有逻辑。

石墩蓄盾重拳：继续使用当前护盾触发与中断规则。不要把展示页中的循环示范当作战斗规则。

## 8. 验证与性能边界

执行：

```bash
node --test tests/*.test.mjs wechat/tests/*.test.mjs
node scripts/build-web.mjs --code-only
node scripts/build-wechat.mjs
```

本次执行结果：272 项测试通过，H5 和微信构建通过。微信主包 249205 字节，总输出 20910719 字节，6 个分包。这是构建产物统计，不是真机性能结论。

重点测试：`tests/painted-transition.test.mjs`，以及 finished-roster、finished-spark、rig-motion、motion、微信相关测试。

现有角色网格每层 36 次三角绘制；保持单姿势时一层，过渡时最多两层。缩短重叠区间、跳过零权重层减少了部分重复绘制，但不应声称绘制次数就是 GPU draw call，也不能据此直接承诺稳定 60fps。

微信真机仍需在目标手机上检查：连续战斗、多人技能、倍速、切页返回、加载与恢复、长时间运行发热和帧时间。低性能设备应先降低非关键特效或更新频率，保持角色比例和真实伤害时序。

## 9. 后续窗口必须遵守的结论

- 现有角色原画是当前正式资产。
- 被认可的是完整原画短过渡方法。
- 分层拼接试作被否定，不要重新推广。
- 石墩重设计已停止，候选图不替换正式资产。
- 原始数据源设计模板优先于后续生成图作为画风依据。
