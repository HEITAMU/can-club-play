# 流畅性改造 — preview.10

## 改动

- 战斗位置、尺寸、动作标记、护盾状态和血条只在数值变化时写 DOM。
- 每帧复用同一次阵型/落脚坐标计算；保留角色原画、体型和原有命中时序。
- 待机角色先集中读取可见区域，再绘制，避免逐个读写交错。
- 连续过关复用同一场景节点；不会每关销毁天气画布和场景资源订阅。
- 图像观察器只扫描新增/移除的元素子树；文字更新不再遍历全部订阅。
- 伤害数字使用最多 48 个可复用节点；回收后清除暴击装饰，避免下一次普通伤害继承边框。
- 角色画布与特效诊断属性不再每帧重复赋值；后台页面暂停绘制循环工作。
- 首场加载完成后，低优先级、逐张下载并解码常用界面与后续街区背景；可选资源失败不会阻断战斗。

## 浏览器实测结果

最终对照确认两个 iframe 实际分别执行 previous.bundle.mjs 与 game.bundle.mjs；不使用仅替换预加载链接的早期无效采样。每轮 12 秒，同一五人阵容；存档归一化后从第一关开始，故这是早期连续过关场景，并非第80关压力测试。

- 基线：132 次帧回调，平均 3.273ms，P95 5.2ms，8219 条 DOM 变更。
- 优化后：134 次帧回调，平均 3.175ms，P95 5.1ms，1095 条 DOM 变更（减少约 86.7%）。
- 两轮均未捕获游戏脚本错误。帧回调耗时仅小幅下降；不能用 DOM 变更减少比例宣称帧率提高同等幅度。
- 云端浏览器帧间隔明显受环境影响（两轮绝大多数间隔超过 33ms）。不声称达到稳定 60fps 或完成手机体验验收。
- 已实际点击伙伴→装备→爪套详情→关闭→出战，详情正常覆盖，返回后正常推进至首领战。
- 正常试玩存档未被测试覆盖；正式 preview.10 页面已从第14关继续推进至第18关。
